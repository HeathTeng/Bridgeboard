# Bridgeboard: notes for Claude Code

Bridgeboard (formerly blackboard-study-hub; subtitle Blackboard 学习面板) is a local web dashboard for Blackboard Learn Ultra, aimed at international students who are not programmers. The owner (HeathTeng) is new to coding and works mostly through Claude Code: explain changes in plain Chinese, one step at a time, and stop to ask before anything irreversible.

## Layout

- `server.js`: zero-dependency Node HTTP server on 127.0.0.1:3100. API routes plus static files from `public/`.
- `lib/bb.js`: loads blackboard-mcp's library (`BB_MCP_PATH`, else the bundled `vendor/blackboard-mcp.js`, else `../blackboard-mcp/dist/index.js`) and shapes data for the page. Also keep-alive and silent renewal.
- `lib/edge-login.js`: one-click sign-in. Opens Edge/Chrome with its own profile (`~/.blackboard-study-hub/browser-profile`), reads cookies over CDP on 127.0.0.1, closes the window.
- Checklist: `lib/checklist.js` (`ChecklistStore`: own items and manual ticks in `~/.blackboard-study-hub/checklist.json`, temp file + rename; memory-only in demo), `lib/checklist-rows.js` (which assignments appear and row order; browser-safe, served as `/checklist-rows.js` like `/status.js`). Routes under `/api/checklist` in `server.js`. When signed out, the page shows only the checklist card (`#main.signed-out`). Deletes wait out a 6-second undo window before reaching the server. Looks like iPhone 提醒事项 (UI redesign step 5): the due time small and grey at the right of a row with the colour capsule, a calendar button (`.cl-cal`) to change it, and a last row `＋ 点这里添加一件事` (`#addRow`, between `#clOwn` and `#clOwnDone`) that turns into a box: Enter adds and keeps it open, Esc closes, empty Enter does nothing. Spec: `docs/dev/module2-checklist.md`.
- Course messages: `lib/messages.js` (threads and messages shaped for the page; bodies become plain text with the library's `htmlToText`), `lib/message-view.js` (filters and relative times; browser-safe, served as `/message-view.js`), `messageThreads` / `messageThread` in `lib/bb.js` (GET only; never `markMessageRead`). Ultra messages have no subject, so a thread is named by who it is with. Each thread links to itself (`messagesLink` with the thread id). Spec: `docs/dev/module7-messages.md`.
- Phone alerts: `lib/push-rules.js` (`planAlerts`: which alerts are due at one check; pure, no clock or network, heavily tested), `lib/push.js` (Bark key / ntfy topic parsing and masking, settings shape and `applyPatch`, senders with a 10 s timeout and one retry, the sent log `~/.blackboard-study-hub/push-sent.json`), `lib/push-service.js` (`PushService`: the 15-minute checker, test, topic changes; demo mode only logs), `lib/autostart.js` (开机自动启动: a `.cmd` in the Startup folder running `start.bat --background` minimised; not .vbs). Settings live under `push` in settings.json; secrets go to the page masked. Routes under `/api/push`; page code in `public/push.js`. `start.bat` passes its arguments on and closes itself when the server exits 0 (already running: it only opened the page; `/api/ping` tells the copies apart). Spec: `docs/dev/module4-push.md`.
- Opening the page without getting stuck: `/api/status` never waits for silent renewal (`quickStatus` in `lib/session-status.js`, used by `status` in `lib/bb.js`): a lapsed session starts renewing in the background and answers `{ signedIn: false, renewing: true }`; after a failed renewal it waits 5 minutes before renewing on its own again. `lib/startup.js` (served as `/startup.js`): the title-card wording (`PHASES`, `STUCK_TEXT`), `retryDelay` (2, 4, 8, 16, then 30 s) and `untilLoaded` (retries timeouts, network trouble and 5xx; not sign-in errors, SERVER_DOWN or 4xx; `onStuck` after 60 s from page open even while a request is out). In `app.js`, `load()` shows the page at once (`showWaiting`: checklist and phone alerts are local; Blackboard sections say 正在从 Blackboard 读取…), polls `/api/status` every 2 s while renewing, and after a minute puts `#stuck` (an apricot box with 再试一次 and 重新连接) in the title card while retries go on behind it (`#whoSpin` is the small ring, still under reduced motion). `api()` in `ui.js` takes `timeoutMs`; a timeout (code TIMEOUT) does not count towards SERVER_DOWN. The server shares one in-flight overview / messages read between requests (`shared` in `server.js`), so retries do not double the load on Blackboard. Tests: `test/startup.test.js` (fake clock).

## Who we design for

Picture the user as extremely impatient, not technical at all, who reads nothing and must be taught everything from zero. For every feature: plain Chinese with no jargon, the explanation visible right where it is needed, empty and error states that say exactly what to do next, one obvious action, and protection against easy mistakes. When proposing a plan, list what such a user could get stuck on. This persona is for catching gaps, not for hiding information: real users are normal students, so keep full details visible (for example, always show full course names, which tell similar subjects apart).

## Rules

- **Read-only.** The panel may link to Blackboard but never changes anything there, not even "read" (agreed with the owner). Never call Blackboard write operations (submit, quiz, mark reviewed, mark…Read). Never set `BLACKBOARD_MCP_ALLOW_WRITES` or use `forceAllowWrite`. `test/readonly.test.js` scans `lib/` and `server.js`: library calls must be on its read-only lists (add a new one there only after checking it reads), and only `lib/push.js` (Bark / ntfy) may send non-GET requests. The library itself reads the to-do list through Blackboard's batch endpoint (an HTTP PUT carrying only GETs, as the Ultra page does); `vendor/` is not changed. Where the page links to Blackboard (截止日期, 课程消息), one `tip` per section says that opening it means acting in Blackboard (messages opened there become read), that the panel itself changes nothing, and that Blackboard opens in a new tab; the FAQ says the same.
- **No secrets in git.** Cookies, cURL captures, HAR files, `~/.blackboard-mcp/`, `~/.blackboard-study-hub/`, API keys and personal paths (e.g. `C:\Users\<name>`) must never be committed or printed in full. Check `git diff --staged` before committing.
- **Stay local.** The server binds 127.0.0.1 only and checks Host/Origin. Do not add anything that sends student data to a third party; the planned AI feature uses the student's own API key, stored locally.
- **The one opt-in exception: phone alerts.** Off by default; only after the student switches them on and a test reached their phone, assignment/course names, due times and links go to Bark (`https://api.day.app`), ntfy (`https://ntfy.sh`) or a self-hosted https server they typed in. No other hosts, never cookies or message text; keys and topics are never logged and reach the page masked.
- **Old names that stay** after the rename (`test/rename.test.js` guards them): the data folder `~/.blackboard-study-hub/`, the calendar UID suffix `@blackboard-study-hub`, the Startup file `blackboard-study-hub.cmd`, the `/api/ping` app id. Changing them loses data or makes duplicates. The GitHub repository was renamed to `HeathTeng/Bridgeboard` on 2026-10-23 (old links redirect); use the new name in links.
- **Zero dependencies** for now: Node built-ins only, so the app can ship as a portable zip.
- **Windows first.** The owner uses Windows + Edge. In Claude Code's `!` shell (Git Bash) use forward slashes in paths.
- UI text is Chinese; README is bilingual; under the logo it has three centred lines: the Chinese title as `<h3>`, the English one in `<sub>`, and the features in Chinese only. Times come from the API in UTC; display in local time.

## Versions and releases

- The owner wants a new release for every change pushed to `main`: bump the patch number by one each time (v0.2.0 → v0.2.1 → v0.2.2 …), set the same number in `package.json` `version`, commit, then push the tag (`git tag v0.2.1 && git push origin v0.2.1`). The Release workflow builds and publishes the Windows zip.
